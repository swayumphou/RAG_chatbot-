# T1.4 - SQLite schema and store API

**Phase:** 1 - Data Model and Manifest
**Status:** TODO


**Depends on:** T1.1, T1.2.
**Goal:** Implement the metadata store from `../spec/INTERFACES.md` §3.

**Spec:**
- Create `store/schema.sql` with the exact tables: `senior`, `senior_alias`, `project`, `authorship`, `document`, `query_log`, `relay_message`.
- `store/db.py`:
  - `DB(path)` opens/creates the database and applies the schema.
  - `upsert_senior(row)`, `upsert_project(row)`, `upsert_authorship(project_id, senior_id, role)`, `upsert_document(row)`.
  - `senior_exists(senior_id) -> bool`.
  - `all_seniors() -> list[dict]`.
  - `lookup_alias(alias_normalized) -> str | None`.
  - `known_names() -> set[str]`, `known_surnames() -> set[str]`.
  - `senior_card(senior_id) -> dict`.
  - `projects_for_senior(senior_id) -> list[dict]` newest first.
  - `log_query(**row)`, `rate(query_id, rating)`, `clicked_project(query_id, project_id)`.
  - `withdrawn_senior_ids() -> set[str]`.
  - `close()`.
- SQL uses parameters, never string interpolation of user values.
- `tech_stack` and `keywords` are stored as JSON strings.
- `created_at`/`updated_at` are ISO-8601.

**Files:**
- Create: `store/schema.sql`, `store/db.py`
- Test: `tests/unit/test_manifest.py` or `tests/unit/test_store.py`

**Interfaces:**
- Consumes: manifest rows.
- Produces: `DB` used by validation, indexing, retrieval, portfolio, answer, and logging.
