# T7.3 - Observability

**Phase:** 7 - Deployment, Configuration, and Observability
**Status:** IN PROGRESS
**Progress:** `logging_config.py` exists and passes `py_compile`/`ruff`/`black`. Ingestion/answer/bot wiring and tests remain.


**Depends on:** T4.4, T5.7, T6.4.
**Goal:** Make failures and latency visible without leaking personal data.

**Spec:**
- Structured logs:
  - `logs/ingest_<timestamp>.json` — per-project pages/chunks/status, point count, model revision, corpus hash;
  - `logs/bot.log` — updates, errors, 429s, dropped messages (no raw IDs);
  - `logs/answer_validation.log` — citation rejections and fallbacks.
- Startup log: embedding tag, LLM tag, Qdrant version, collection name, point count.
- Metrics/counters:
  - retrieval latency (P50/P95 from `query_log`);
  - abstention rate;
  - LLM rejection rate;
  - Telegram 429 count;
  - failed sends;
  - zero-result query count.
- Alerts/thresholds from Architecture §14: P95 > 2 s, abstention > 40%, rejection > 10%, 429 > 5/hour.
- No raw Telegram ID, token, contact field, or full document text in logs.
