# T6.4 - Query logging and click tracking

**Phase:** 6 - Evaluation and Training-Pair Flywheel
**Status:** TODO


**Depends on:** T5.2, T1.4.
**Goal:** Log every interaction in a shape that can become training data.

**Spec:**
- `query_log` fields: `query_id`, `surface`, `tg_user_hash`, `tg_message_id`, `raw_query`, `normalized_query`, `intent`, `resolved_senior`, `retrieved_json`, `clicked_project`, `rating`, `latency_ms`, `created_at`.
- `retrieved_json` is a list of `{project_id, rank, score, matched_by}`.
- `clicked_project` is set when a user taps `Abstract` or `Portfolio` on a project card.
- Rating is `1`, `-1`, or `NULL`.
- Logging is non-blocking; a logging failure must not fail the answer.
- Telegram IDs are salted hashes; never raw.
- `surface` is `telegram` or `cli`.
- The log is the only source for T6.5; no separate click store.

**Files:**
- Modify: `store/db.py`, `bot/handlers.py`, `answer/service.py`
- Test: `tests/unit/test_metrics.py` and `tests/integration/test_bot_pipeline.py`

**Interfaces:**
- Produces: `query_log` rows consumed by T6.5.

**Steps:**
- [ ] Add `clicked_project` handling.
- [ ] Add the `retrieved_json` shape.
- [ ] Add tests for a full row and a failed log write.
- [ ] Add a bot test that tapping `Abstract` sets `clicked_project`.

**Acceptance:**
- [ ] Every interaction writes one row.
- [ ] The row contains ranks and scores.
- [ ] A click is recorded.
- [ ] No raw Telegram ID or contact field is logged.

**Tests:** `tests/unit/test_metrics.py` and `tests/integration/test_bot_pipeline.py`

**Out of scope:** analytics dashboards.
