# T4.2 - Relevance gate and abstention

**Phase:** 4 - Extractive-First Answer Layer
**Status:** TODO


**Depends on:** T4.1, T3.3.
**Goal:** Abstain below the measured dense threshold and never call the LLM there.

**Spec:**
- Gate uses the **top project's `dense_score`**, not the fused RRF score.
- If no project passes `abstain_threshold`:
  - return `mode="abstain"`;
  - `answer=ABSTAIN`;
  - `weak_matches` = up to 3 projects labelled low confidence;
  - no LLM call.
- The threshold default is `0.45` only as a placeholder; Phase 6 replaces it with the swept value.
- A query with no results returns the same abstain result with `weak_matches=[]`.
- Log the top score and the threshold used for the decision.

**Files:**
- Modify: `answer/service.py`
- Test: `tests/unit/test_answer.py::test_gate_abstains_without_llm`

**Interfaces:**
- Consumes: `RetrievedProject.dense_score`.
- Produces: abstain `AnswerResult`.

**Steps:**
- [ ] Implement the gate.
- [ ] Add a test with a fake retriever returning a low score and a spy LLM that must not be called.
- [ ] Add a test that a high score proceeds to extractive.
- [ ] Add a test that `weak_matches` is capped at 3.

**Acceptance:**
- [ ] Below the gate: `mode="abstain"`, no LLM.
- [ ] Above the gate: extractive answer.
- [ ] The abstain text is exactly `ABSTAIN`.
- [ ] Weak matches are labelled low confidence.
