# T3.5 - Senior entity resolution

**Phase:** 3 - Five-Intent Retrieval
**Status:** REVIEW
**Note:** The fuzzy step scans every active senior's names and aliases (`DB.alias_directory()`), which includes the `all_seniors()` names. `sokdaraa` is an alias in the T1.1 fixture, so it resolves via alias (1.00); `sok daraa` tests the fuzzy path and `sreyneang` the text-index path.


**Depends on:** T3.1, T1.4, T2.8.
**Goal:** Resolve a name to exactly one senior, or return ambiguity/not-found candidates.

**Spec:**
- Resolution order:
  1. exact `senior_alias.alias_normalized` → `resolved`, confidence `1.00`, `via="alias"`;
  2. Qdrant full-text on `author_names_normalized` → exactly one senior → `resolved`, confidence `0.90`, `via="text_index"`;
  3. `rapidfuzz.token_set_ratio ≥ 88` over the full directory → exactly one → `resolved`, confidence `score/100`, `via="fuzzy"`.
- Several fuzzy matches → `ambiguous` with up to 5 candidates, each with `senior_id`, name, program, cohort year, score.
- No match → `not_found` with up to 3 closest candidates, marked “not confirmed”.
- Never auto-merge two seniors with the same name.
- `sokdaraa` must resolve through the text index or fuzzy path.
- Khmer names must resolve through the alias table or fuzzy path; `rapidfuzz` handles Khmer strings.
