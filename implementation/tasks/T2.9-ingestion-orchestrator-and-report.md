# T2.9 - Ingestion orchestrator and report

**Phase:** 2 - Project-Aware Ingestion and Indexing
**Status:** TODO


**Depends on:** T1.5, T2.8.
**Goal:** Run the full pipeline and write a run report that proves what happened.

**Spec:**
- `python -m ingestion.run --projects ... --seniors ... --corpus ... [--rebuild]`.
- Read only the paths passed on the command line. Ignore `data/reference/` completely; it is migrated legacy curriculum data, not senior projects.
- Order:
  1. `validate_manifest`; exit 2 on errors before any Qdrant write.
  2. Parse every granted project's files.
  3. Chunk.
  4. Embed + upsert (or update) into Qdrant.
  5. Rebuild SQLite metadata from the manifest.
  6. Verify point count and payload.
  7. Write `logs/ingest_<timestamp>.json`.
- `--rebuild` deletes/recreates the collection; without it, upsert is incremental.
- `permission != granted` and withdrawn seniors are skipped, not indexed.
- A project with zero chunks is reported as `failed`, not `ok`.
- A parse failure is reported and excluded; the run continues.
- The report includes model revision, corpus hash, per-project pages/chunks/status, point count, timestamps, and errors.

**Files:**
- Create: `ingestion/run.py`
- Test: `tests/integration/test_ingestion_pipeline.py`

**Interfaces:**
- Consumes: every ingestion module.
- Produces: a populated Qdrant + SQLite, and a JSON report.
