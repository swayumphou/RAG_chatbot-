# T2.1 - Parser contract and registry

**Phase:** 2 - Project-Aware Ingestion and Indexing
**Status:** REVIEW


**Depends on:** T1.4.
**Goal:** Define the data model every parser returns and a registry that dispatches by file extension.

**Spec:**
- `ingestion/parsers/base.py`:
  - `Page(number, text, headings)`.
  - `ParsedDocument(doc_id, project_id, doc_type, file_path, sha256, pages, parse_status, parser, page_count)`.
  - `to_langchain_documents(project)` returns one `Document` per page with metadata `doc_id`, `project_id`, `page_number`, `parse_status`, `parser`.
- `doc_id = f"{project_id}__{Path(path).name}"`.
- `sha256` is the file's SHA-256.
- `parse_status` is `ok`, `ocr`, or `failed`.
- `ingestion/parsers/__init__.py` exposes `parse_document(path, project) -> ParsedDocument` and a registry keyed by `.pdf`, `.docx`, `.pptx`, `.md`, `.txt`.
- Unsupported extension raises `ValueError` with the file name.
- A parser may never return a `ParsedDocument` with `parse_status="ok"` and zero pages; it returns `failed`.

**Files:**
- Create: `ingestion/parsers/base.py`, `ingestion/parsers/__init__.py`
- Test: `tests/unit/test_parsers.py::test_parser_registry_and_empty_document`

**Interfaces:**
- Produces: `Page`, `ParsedDocument`, `parse_document` (see `../spec/INTERFACES.md` §5.1).

**Acceptance:**

- [x] An unsupported extension raises with a clear message.
- [x] A parser with no pages returns `failed`, never `ok`.
