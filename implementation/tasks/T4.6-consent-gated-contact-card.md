# T4.6 - Consent-gated contact card

**Phase:** 4 - Extractive-First Answer Layer
**Status:** TODO


**Depends on:** T1.4, T4.1.
**Goal:** Render contact details only with consent and keep them out of the LLM prompt.

**Spec:**
- `answer/consent.py`:
  - `contact_card(senior) -> dict | None`;
  - returns GitHub/LinkedIn/website/email only when `consent_public_contact=1`;
  - returns `None` otherwise, with `CONSENT_DENIED`.
  - `can_relay(senior) -> bool` requires `consent_relay=1` and `telegram_user_hash` set.
- Phone numbers are never stored or returned.
- The answer service attaches the card to a portfolio result; it never adds it to `citations` or the prompt.
- `contact_email` is included only with public-contact consent.

**Files:**
- Create: `answer/consent.py`
- Modify: `answer/service.py`
- Test: `tests/unit/test_consent.py`

**Interfaces:**
- Produces: `contact_card`, `can_relay`.

**Steps:**
- [ ] Implement the consent checks.
- [ ] Add tests for consent true/false and relay true/false.
- [ ] Add a test that the LLM prompt never contains an email or GitHub URL.

**Acceptance:**
- [ ] Consent false → no contact block.
- [ ] Consent true → only the allowed professional fields.
- [ ] Relay requires consent and a started bot.
- [ ] Contact data is absent from prompts.
