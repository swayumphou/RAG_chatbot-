# T6.3 - Evaluation runner, threshold sweep, and baseline

**Phase:** 6 - Evaluation and Training-Pair Flywheel
**Status:** REVIEW
**Note:** A smoke run (real bge-m3, embedded Qdrant, fixture index) chose threshold 0.49. `eval/baseline.json` stays empty until an approved run on the Qdrant server.


**Depends on:** T6.2, T4.2.
**Goal:** Run the golden set through `answer.service.answer()` and commit a reproducible baseline.

**Spec:**
- `python -m eval.run_eval --golden eval/golden_set.csv --sweep-threshold`.
- Calls `answer.service.answer()` directly; Telegram is never in the path.
- Prints one row per slice: `n`, Recall@5, MRR@10, nDCG@10, name top-1, abstention precision.
- `--sweep-threshold` prints a table and chooses the smallest threshold reaching abstention precision ≥ 0.95 without dropping topic Recall@5 below 0.90.
- Writes `eval/last_report.json` with:
  - golden-set SHA-256;
  - model tags (`embed_model`, `llm_model`, `qdrant_version`);
  - threshold;
  - per-slice metrics;
  - per-query rows with route, mode, top score, rank.
- `eval/baseline.json` is committed after the first full run.
- A missing slice or model-tag mismatch is an error.

**Files:**
- Create: `eval/run_eval.py`, `eval/baseline.json` (after the first run)
- Test: `tests/integration/test_eval_pipeline.py`

**Interfaces:**
- Consumes: `answer.service.answer`, metrics.
- Produces: baseline JSON and the chosen threshold.
