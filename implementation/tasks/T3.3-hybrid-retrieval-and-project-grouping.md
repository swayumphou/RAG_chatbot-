# T3.3 - Hybrid retrieval and project grouping

**Phase:** 3 - Five-Intent Retrieval
**Status:** TODO


**Depends on:** T2.8, T3.1.
**Goal:** Dense + sparse prefetch, RRF fusion, grouping by `project_id`, and `matched_by`.

**Spec:**
- `hybrid_retrieve(client, embedder, lexical_query, flt=None, prefetch_k=40, fusion_limit=10)`:
  - dense prefetch 40, sparse prefetch 40;
  - `models.FusionQuery(fusion=models.Fusion.RRF)` with `k=60`;
  - optional `query_filter=flt`;
  - limit 10 before grouping;
  - return fused points with payload.
- `group_by_project(points, top_k=5)`:
  - keep the highest-scoring point per `project_id`;
  - sort descending by fused score;
  - return at most 5 distinct projects.
- `RetrievedProject` includes `dense_score` (the project's best dense cosine) and `matched_by` (`dense`, `lexical`, or `both`).
- `matched_by` is computed from membership in the two prefetch result sets, not guessed from the payload.
- Grouping happens **after** fusion and **before** truncation.
- The gate uses `dense_score`, not the RRF score.

**Files:**
- Create: `retrieval/hybrid.py`
- Test: `tests/unit/test_hybrid.py`

**Interfaces:**
- Produces: `hybrid_retrieve`, `group_by_project`, `RetrievedProject`.
- Consumes: Qdrant client, `Embedder`.

**Steps:**
