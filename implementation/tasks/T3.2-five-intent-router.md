# T3.2 - Five-intent router

**Phase:** 3 - Five-Intent Retrieval
**Status:** REVIEW


**Depends on:** T3.1, T1.4.
**Goal:** Classify a query into `TOPIC_SEARCH`, `SENIOR_LOOKUP`, `PORTFOLIO`, `FACET_BROWSE`, or `ANSWER`, with entities.

**Spec:**
- `YEAR_RE` matches a four-digit cohort year (`20xx`).
- `PROGRAM_RE` matches `DSE|ITE|TEE|BE|FTCE` case-insensitively.
- `QUESTION_RE` matches `who|what|which|when|where|why|has anyone|is there|are there`.
- `PORTFOLIO_RE` matches `portfolio|projects? (by|of)|works of`.
- `route(query, db) -> RoutedQuery`:
  - normalize;
  - exact known-name or exact surname signal → `SENIOR_LOOKUP`;
  - portfolio phrase → `PORTFOLIO`;
  - question word → `ANSWER`;
  - 2–4 tokens, no project/thesis/system/using/with, token intersects known surnames → `SENIOR_LOOKUP`;
  - year/program and ≤ 3 tokens → `FACET_BROWSE`;
  - otherwise `TOPIC_SEARCH`.
- Bias: when in doubt, `TOPIC_SEARCH`. A wrong senior lookup is the worst outcome.
- Extract `name_span` and `topic_span` for multi-intent.
- `db` provides `known_names()` and `known_surnames()`.
