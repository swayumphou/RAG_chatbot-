# T1.6 - Manifest diff and validation CLI

**Phase:** 1 - Data Model and Manifest
**Status:** TODO


**Depends on:** T1.5.
**Goal:** Make validation runnable and make re-ingestion explain what changed.

**Spec:**
- `diff_manifests(old_projects, old_seniors, new_projects, new_seniors) -> dict` returns:
  `{"projects": {"added": [...], "updated": [...], "removed": [...]}, "seniors": {...}}`.
- “Updated” means the same ID with any changed field.
- CLI:
  `python -m ingestion.validate_manifest --projects data/projects.csv --seniors data/seniors.csv --corpus data/corpus`
- Exit code `0` on success, `1` on errors.
- Print warnings and errors with row numbers; print the corpus hash and counts.
- A `--json` flag writes the report to stdout as JSON.

**Files:**
- Create: `ingestion/validate_manifest.py` (CLI block), `tests/unit/test_manifest.py`
- Modify: none

**Interfaces:**
- Consumes: `validate_manifest`.
- Produces: CLI used by the pre-demo checklist and CI.

**Steps:**
- [ ] Implement the diff on dictionaries keyed by ID.
- [ ] Add the CLI and exit codes.
- [ ] Add a test for added/updated/removed.
- [ ] Add a test that a malformed manifest exits `1`.

**Acceptance:**
- [ ] `--projects/--seniors/--corpus` validates the fixture.
