# T3.7 - Multi-intent intersection

**Phase:** 3 - Five-Intent Retrieval
**Status:** TODO


**Depends on:** T3.2, T3.3, T3.5.
**Goal:** Handle “Sok Dara’s OCR project” without dropping either half.

**Spec:**
- Decompose into `SENIOR_LOOKUP(name_span)` + `TOPIC_SEARCH(topic_span)`.
- Run both.
- Intersect topic results on `senior_ids`.
- Non-empty intersection → matching project first, then the senior’s other projects.
- Empty intersection → all of the senior’s projects plus:
  `None of <name>'s indexed projects matched '<topic>'.`
- Never silently drop the topic or the senior.
- If the name is ambiguous, return the candidate keyboard; do not run the topic half.

**Files:**
- Create: `retrieval/intent.py` (decomposition helper), `answer/service.py` (orchestration hook in Phase 4)
- Test: `tests/unit/test_intent.py::test_multi_intent_decomposition`

**Interfaces:**
- Produces: `decompose_multi_intent(query, db) -> tuple[RoutedQuery, RoutedQuery] | None`.

**Steps:**
- [ ] Detect `"<name>'s <topic>"` and `"<name> <topic> project"`.
- [ ] Return the two routed queries.
- [ ] Add tests for non-empty and empty intersection at the service level in Phase 4.

**Acceptance:**

- [ ] An ambiguous name short-circuits to candidates.
