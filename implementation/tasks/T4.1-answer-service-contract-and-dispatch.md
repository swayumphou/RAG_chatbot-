# T4.1 - Answer service contract and dispatch

**Phase:** 4 - Extractive-First Answer Layer
**Status:** REVIEW
**Note:** Extra `AnswerResult` fields and modes are listed in `INTERFACES.md` §5.3 "Additions". `intent=`/`facets=` overrides were removed; Phase 5 can propose them if `/senior` or facet chips need them. Query logging moves to T6.4.


**Depends on:** T3.8.
**Goal:** Implement `answer.service.answer()` as the single entry point for the bot, CLI, and evaluator.

**Spec:**
- Signature: `answer(query, client, embedder, db, abstain_threshold=0.45, enable_llm=False) -> AnswerResult`.
- Dispatch:
  - `SENIOR_LOOKUP` / `PORTFOLIO` → resolve → portfolio; ambiguous/not_found returns the structured status.
  - `FACET_BROWSE` → `build_facet_filter` + `hybrid_retrieve` + `facet_counts`.
  - `ANSWER` / `TOPIC_SEARCH` → hybrid retrieve → gate → extractive/LLM.
- Multi-intent → T3.7 path.
- The result contains `query_id`, `route`, `mode`, `answer`, `citations`, `projects`, `portfolio`, `weak_matches`, `normalized_query`, `intent`, `resolved_senior`, `latency_ms`.
- Logging is a separate call; the service returns the data it needs.
- The service never sends Telegram messages and never formats HTML.

**Files:**
- Create: `answer/service.py`
- Test: `tests/unit/test_answer.py::test_service_dispatch_and_result_shape`

**Interfaces:**
- Produces: `answer`, `AnswerResult`.
- Consumes: `route`, `hybrid_retrieve`, `resolve_senior`, `portfolio`, `build_facet_filter`.
