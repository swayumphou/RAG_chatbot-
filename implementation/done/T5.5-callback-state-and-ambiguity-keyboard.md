**Note:** `PagerState` also keeps the result cards, so `Next` needs no new search. An expired key asks the user to search again (INTERFACES §5.5).


**Depends on:** T5.3, T3.5.
**Goal:** Handle ambiguity and pagination without putting long data in callback payloads.

**Spec:**
- `bot/state.py`:
  - TTL map, 600 s, max 500 entries;
  - `put_candidates(senior_ids) -> state_key`;
  - `get_candidates(state_key) -> list[str] | None`;
  - `put_pager(query_id, page)`, `get_pager(key)`.
- Ambiguous name:
  - text: `I found N seniors named <name>. Which one?`;
  - one button per candidate: `Name — PROGRAM YEAR`;
  - callback: `pick:<state_key>:<index>`;
  - no automatic winner.
- Expired state → reprompt with the original query.
- Callback data ≤ 64 bytes; the candidate list never goes into the button.
- `pick` resolves the candidate and opens the portfolio.
