# T5.8 - Consent-gated relay

**Phase:** 5 - Telegram Interface
**Status:** DONE
**Completed:** 2026-11-28
**Commit:** 2a63e3f
**Reviewed by:** swayumphou
**Note:** A senior's `telegram_user_hash` is set by an admin (`DB.set_telegram_user_hash`); the spec has no claim flow. Someone who has not used the bot since it started is not reachable: the message stays `queued` until the senior next opens the bot. Replies use the `rr:` button. Limit: 3 messages per sender per hour.


**Depends on:** T4.6, T5.1.
**Goal:** Let a student message a consenting senior without revealing either identity.

**Spec:**
- A portfolio shows `Send a message` only when `can_relay(senior)`.
- Flow:
  1. student taps the button;
  2. bot asks for the message body;
  3. store `relay_message(status="queued", from_hash=sha256(user_id+salt))`;
  4. DM the senior only if `consent_relay=1` and `telegram_user_hash` is set;
  5. senior replies → forwarded back by `relay_id`;
  6. neither party sees the other's Telegram identity.
- If consent is absent, show `CONSENT_DENIED` and no button.
- A message is never forwarded to a senior who has not started the bot.
- Rate-limit relay messages per sender; drop and log after the limit.
